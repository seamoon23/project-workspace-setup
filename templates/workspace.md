> 이 저장소의 **사이트맵**. 파일을 어디에 두고 어디서 찾을지는 이 문서를 기준으로 한다.
> 작업 규칙(운영 하한·절대 규칙·검증)은 `PROJECT.md`, 프로젝트 맥락·기존 지침은 `CLAUDE.md` 참조. 최종 갱신: {DATE}

---

## 3분할 원칙

| 폴더 | 성격 | git | 판단 기준 |
| --- | --- | --- | --- |
| `dev/` | **로컬 전용** | 제외 | 내 PC 환경에 묶인 것 (배포 스크립트, 세션 메모, 폐기 코드) |
| `docs/` | **문서·양식** | 추적 | 계속 참조·갱신되는 저술 원본. 소실되면 복구 불가한 것 |
| `works/` | **요청작업** | 제외 | 특정 시점 1회성. 요청 원본 + 그 산출물 |

**헷갈릴 때**: "다음 달에도 이 파일을 열어볼까?" → 그렇다 `docs/` · 아니다 `works/`

```

README.md            프로젝트 소개
src/                 애플리케이션 소스
```

## works/ — 요청작업 (git 제외)

**폴더 규칙**: `YYYYMMDD_작업제목/`

```
<작업폴더>/
  요청원본/      받은 요청 문서 원본 (pptx·hwpx·메일 캡처 등)
  report/       산출물 — 작업정리·회신자료·리포트
```

산출물은 **작업 폴더 하위 `report/`** 에 배출한다. 요청 맥락과 결과가 붙어 있어야 나중에 찾는다.

```
_backlog/       작업 대기 목록 (지시할 때만 참고)
```

## 규칙

1. **반출본을 저장소에 중복 보관하지 않는다** — 필요할 때 원본에서 생성. 사본이 남으면 원본과 어긋난다.
2. **works/ 산출물은 재생성 가능한 상태로 둔다** — 생성 스크립트나 절차 md를 함께 남긴다.
3. **폐기 코드는 지우지 말고 `dev/archive/`로** — 되살릴 일이 생긴다.
